Why Intake

Less invoice-specific glue in your application.

XML libraries can expose nodes. Intake provides a deliberately narrower boundary for ERP ingestion: validation evidence, a stable response schema and a refusal when a document cannot be represented safely.

1

Validate first

Reports which XSD, Schematron and PDF/A layers ran or were skipped. Incomplete validation cannot become a successful strict serialization.

2

Normalize strictly

Maps supported CII and UBL invoices to schema v2 without tolerant XML recovery, placeholder values or silently dropped material groups.

3

Explain refusals

Returns readable validation context or stable mapping diagnostics with a code, source path and message instead of a plausible partial invoice.

Questions

Before you integrate

Does Factur-X Engine send invoice data to a hosted API?

No. The engine runs in your container. You control the host, network, storage, logs and access policy.

Does a successful response guarantee fiscal or regulatory conformity?

No. Results only describe the rules and tools that actually ran. Inspect validation completeness and retain your own business, accounting and acceptance controls.

What happens when Intake cannot map a document safely?

It returns HTTP 422 with stable diagnostics. It does not recover malformed XML, invent required business values or label a partial mapping as successful.

Is the €299 licence available now?

Not through a public paid checkout. The displayed price is the commercial hypothesis being tested. You can evaluate the complete Intake path for 30 days at €0.
